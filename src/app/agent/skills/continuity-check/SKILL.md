# 连贯性与一致性审查

## 何时使用
- 章节定稿前的一致性核查
- 读者反馈「前后矛盾」，需要定位问题
- 跨卷衔接检查
- 定期全书伏笔盘点

## 审查原则
- **只读**：用 `read_file` / `grep` / `glob` 检索证据，不修改文件。输出问题清单交给用户或主代理决定。
- **有据**：每个问题必须给出定位（卷 / 章 / 原文片段），不空泛断言。
- **分级**：区分「硬伤」（必须改）与「建议」（可改可不改）。

## 五维检查表
### 1. 时间线
- 事件先后顺序是否合理（有无「先发生后起因」）
- 时间跨度：季节、昼夜、年龄增长是否连贯
- 「三年后」「次日」等时间标记是否自相矛盾
- 用 `grep` 搜时间词（年后 / 月后 / 次日 / 翌日 / 翌晨）建立时间轴

### 2. 人物状态
- 外貌、伤势、位置在章节间是否连续（上章重伤，下章健步如飞？）
- 人物关系、称谓、身份是否前后一致
- 性格是否 OOC（做出与设定不符的决定而无铺垫）
- 已死亡 / 已离场人物是否「复活」出场

### 3. 设定一致性
- 是否违反附录 A「世界观」（力量体系规则、地理、势力）
- 是否违反附录 C「战力层次」（弱者无故胜强者、境界压制失效）
- 专有名词（功法 / 地名 / 组织 / 物品）拼写与设定是否统一
- 用 `grep` 搜专有名词，核对各处用法一致

### 4. 伏笔
- 列出所有埋设的伏笔，标注是否已回收
- 「只埋不收」：超过合理章数仍未回收的伏笔
- 「无源之水」：突然出现、前文毫无铺垫的关键道具 / 能力 / 人物
- 回收是否与前文矛盾（回收时的设定与埋设时不符）

### 5. 因果逻辑
- 人物动机是否充分（为什么这样做）
- 巧合是否过多（靠运气而非人物行动解决困境）
- 信息合理性：人物是否知道他不该知道的信息（视角泄露）

## 输出格式
```
## 连贯性审查报告

### 硬伤（建议修正）
1. [卷X 章Y ↔ 卷X 章Z] 问题描述
   - 原文A：「……」
   - 原文B：「……」
   - 矛盾点：……
   - 修改建议：……

### 建议（可选优化）
1. [定位] 描述 + 建议

### 伏笔盘点
| 伏笔 | 埋设章 | 状态 | 备注 |
| --- | --- | --- | --- |

### 结论
总体一致性评估 + 最需优先处理的问题
```

## 检索技巧
- `grep` 人物名 → 核对该人物所有出场的一致性
- `grep` 时间词 → 重建时间轴
- `grep` 专有名词 → 核对术语统一
- `read_file` 大纲附录 → 取得权威设定基准
- `glob` `chapters/**/*.md` → 批量确认章节范围
