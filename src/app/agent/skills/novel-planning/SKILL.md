# 大纲与分卷节奏规划

## 何时使用
- 新书立项，需要从梗概推导全书骨架
- 现有大纲节奏失衡（拖沓 / 高潮过密 / 断更式收尾），需要重排
- 新增一卷或一个故事弧，需要确定它在整体结构中的位置
- 需要检查伏笔是否「只埋不收」或「收得太急」

## 工作流程
1. 先 `read_file` 读大纲全文与 `novel.yaml`，确认题材、梗概、已有卷章结构。
2. 确认目标：本次是「新建骨架」还是「局部调整」。局部调整时**只动相关小节**，不要重写全书。
3. 按下方检查表逐项评估，形成结论后再落笔。
4. 用 `edit_file` 精准替换目标小节；新增卷章时在正确位置插入小节。
5. 改完 `read_file` 回读自检，确认标题层级未被破坏。

## 三级大纲结构
- **一级（卷）**：一个完整故事弧，有独立的起承转合与阶段性目标达成。单卷建议 15–40 章。
- **二级（章）**：一个场景群或一次冲突推进，章末应有钩子（悬念 / 转折 / 情绪落点）。单章建议 2000–4000 字。
- **三级（情节点）**：章内的 2–4 个关键动作，写进 `- 简介：`，是正文生成的直接依据。

## 节奏检查表
| 维度 | 判断标准 | 失衡处理 |
| --- | --- | --- |
| 冲突密度 | 每 3–5 章应有一次实质冲突升级 | 过疏 → 合并过渡章；过密 → 插入缓冲章处理情绪与关系 |
| 高潮分布 | 卷末高潮强度应高于卷内小高潮 | 卷末平淡 → 前移伏笔回收，把最强牌留给卷末 |
| 信息释放 | 世界观 / 真相分批给出，不一次倾倒 | 前期设定倾泻 → 拆散到冲突中自然带出 |
| 人物弧光 | 主要人物每卷应有可见变化 | 人物停滞 → 安排一次代价明确的抉择 |
| 视角切换 | 切换有明确叙事理由 | 无意义跳视角 → 合并到主视角 |

## 伏笔规划
- 每条伏笔登记三要素：**埋设章 → 强化章（可选）→ 回收章**。
- 短伏笔（3–8 章内回收）用于章末钩子；长伏笔（跨卷）用于卷末反转。
- 检查「只埋不收」：列出所有埋设点，确认每个都有回收位置，无归属的删掉或补回收。
- 回收时优先「出乎意料但回想合理」，避免靠新设定硬圆。

## 输出格式（硬性）
```
# 第X卷 卷名

## 第X章 章名

- 简介：（必填）本章剧情要点，AI 生成正文时以此为依据。
- 衔接要点：（建议填写）与上一章的承接、伏笔、人物状态变化。
```

## 禁止事项
- **不要手工修改 `sort_order`**：卷章顺序由大纲小节先后派生，调整顺序就调整小节位置。
- **不要新建或重命名章节文件**：文件名含 ID，改名会让修订快照、摘要、阅读进度全部失效。
- 不要删除附录 A–D（世界观 / 人物 / 战力 / 写作要求），可以补充内容。
- 不要输出「未命名」「第一卷」这类占位名——卷章名必须具体（显式命名铁律）。
