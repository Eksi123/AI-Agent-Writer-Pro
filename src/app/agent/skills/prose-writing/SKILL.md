# 正文写作与场景构建

## 何时使用
- 生成新章节正文
- 续写中断的章节
- 已有正文需要扩写某个场景或补充细节

## 动笔前必做（顺序不可调换）
1. `read_file` 大纲，定位本章小节，**抄录「简介」与「衔接要点」全文**作为写作依据。
2. `read_file` 附录 D「写作要求」，确认视角、人称、文风、禁忌。
3. `read_file` 附录 B「人物角色」，确认出场人物的身份、性格、说话方式。
4. 读前情提要（或 `read_file` 上一章），确认人物当前状态、地点、未解决的悬念。
5. 若本章简介缺失或为空 → **停下来询问用户**，不要凭空编造剧情。

## 场景构建五要素
每个场景动笔前在心里确认：
- **目标**：视角人物本场想要什么（具体、可失败）
- **冲突**：什么在阻碍（人 / 环境 / 内心）
- **转折**：场景结束时局面发生了什么变化
- **感官**：至少调动两种非视觉感官（听觉 / 嗅觉 / 触觉 / 温度 / 体感）
- **落点**：章末钩子（悬念 / 抉择 / 情绪余韵）

## 叙述控制
| 手法 | 用法 | 常见错误 |
| --- | --- | --- |
| 展示 vs 讲述 | 情绪用动作与生理反应展示，背景信息可讲述 | 通篇「他感到愤怒」而不写表现 |
| 节奏 | 动作场面短句、密集动词；抒情场面长句、留白 | 打斗写得绵长，告白写得仓促 |
| 对话 | 每人有可辨识的口头禅与句式长度；少用「说」之外的对话标签堆砌 | 所有人说话一个腔调 |
| 视角 | 一章内不无故跳视角；跳视角用空行分隔 | 上帝视角泄露人物不该知道的信息 |
| 描写密度 | 首次出现的场景多写，熟悉的场景一笔带过 | 每章都重新描写同一间屋子 |

## 中文字句规范
- 避免「的地得」误用；避免「进行了 + 动词」的冗余结构（「进行了调查」→「调查」）。
- 慎用翻译腔：「这是一个……的男人」「不得不说」「某种意义上」。
- 数字：叙述用汉字（三人、五更），精确数据用阿拉伯数字。
- 标点：中文全角；对话内句末标点在引号内；省略号用「……」，破折号用「——」。
- 每段建议 2–5 句，避免大段密集文字；对话独立成段。

## 禁忌（除非大纲明确要求）
- 引入大纲简介之外的重大剧情（新主要人物、重大设定变更、主角死亡）
- 用「突然」强行制造转折；用巧合解决主角自己造成的困境
- 大段复制粘贴设定说明文（附录内容要化入情节）
- 写「（此处省略若干字）」这类占位文字
- 在正文里出现作者按、章节说明等元信息

## 落盘要求（最重要）
- **必须调用 `write_file` / `edit_file` 把正文写进 `chapters/v{卷ID}/c{章ID}.md`**。用户在界面上只能看到落盘内容，回答里贴的正文等于没写。
- 保留文件顶部的 frontmatter（`---` 之间的部分）原样不动，只写正文。
- 整章覆盖属于高危写入，会触发审批卡片——请在调用前说明你要写什么、依据哪条简介。
- 写完 `read_file` 回读，确认字数与内容完整。
