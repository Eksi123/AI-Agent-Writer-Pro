Agent项目组织优化，除根目录文件外要求只包含以下目录，并且删掉多余的文件（ knowleage是否多余？）

#### Tools：

- （1）把tools和skills合并在一起，原内置工具（包括web_research）放在 /tools/builtin下，用户自建skill放在/tools/users下
- （2）检查一下Tools调用是不是 渐进披露式调用，以及Tools和SubAgents的绑定关系是不是准确的
- （3）在AI设置-写作技能中，所有的技能功能都新增[启用]设置、去掉原[查看]设置，且用户自建技能新增[删除]设置，三个设置的顺序是启用、编辑、删除。未启用的技能不可被主agent调用，不可被子agent子代理绑定使用，内置工具的启用和编辑是置灰状态不可修改

#### SubAgents：

- （1）删除原来的旧子代理，整合新增四个内置子代理Planner、Writer、Reviewer、Web_Searcher，放在/subagents/builtin下，其中Writer负责大纲小说的撰写修改全流程，Reviewer作为大纲和小说内容的检查者。此外用户自建子代理放在/subagents/user里。所有子代理的提示词都放在对应目录下
- （2）检查一下subagent（子代理）和主agent之间的逻辑是不是：主 Agent 统筹决策 → 派发子Agent任务 → 子 Agent 独立执行（不继承主Agent上下文） → 结果回传汇总，子Agent调用也是渐进披露式
- （3）在AI设置-写作子代理中同时显示内置子代理和用户子代理，内置子代理有 启用、编辑和恢复默认 三个设置，用户子代理有 启用、编辑、删除两个设置，所有设置的顺序是 启用、编辑、删除/恢复默认
- （4）在新建子代理弹窗，名称输入框下方用小红字提示“尽量不要与内置子代理功能重复”，万一实际工作中内置子代理功能和用户子代理存在重复，则优先内置子代理

#### Workflows

- 把写作过程中的一些固定流程（比如四阶段门禁）都放在 agent/workflows下面，如果内置子代理（比如Writer和Reviewer）的工作涉及到其中某些固定流程，那么子代理和工作流workflows就需要存在绑定关系。此外你帮我想想还有那些固定流程是有必要的？

#### Loop

- Agent运行的核心代码放在这里（其他涉及到安全措施的放在harness下面），包括llm调用、主Agent创建和Loop调用、上下文处理、Agent处理及回复结果的发送、子Agent的调用统筹、工具的注册调用、系统提示词等等，代码脚本数据文件可以放在/loop目录下，也可以按照分类放在/loop/xxx下

#### Harness

- （把所有Agent运行中的安全相关措施（Agent运行本身必备流程不考虑，Wrokflows中写作相关的流程措施不考虑）都放在agent/harness/xxx目录下（其中xxx是对应分类的安全领域名称），比如沙箱措施放在agent/harness/sandbox下，llm容错降级等安全措施放在agent/harness/llm下等等，你可以先计划出一个分类整理方案并实施，如果有不确定有争议的就询问我

#### Tracing

- 所有涉及到Agent运行消息和日志 记录、归类、处理和传递等措施，都放在这个目录下

#### More

- 除上述模块外，其他需要用到但不适合上述分类的放在这个目录下，比如mcp调用天气组件，langfuse观测等等
